## 2. 本轮代码修复（对应 08-04 报告第 6 节）

### 2.1 术语解析产物结构化（Step 1）

`knowledge_v2/terminology.py` 的 `resolve()` 新增 `query_expansions` 结构化字段：

- `matched_terms`：每个匹配的表面形式 → 规范名、concept_id、关系类型；
- `canonical_entities`：规范概念聚合及其别名；
- `blocked_expansions`：被上下文门控拦截的扩展；
- `ambiguous_surfaces`：未消歧表面形式；
- `search_obligations.required_pairs`：**原词 → 规范名的必搜对**，由检索器/搜索
  契约直接消费并记录审计，不再要求模型自行复述扩展词。

`kg_raw_codex/terminology_contract.py` 的 `build_terminology_search_contract`
优先消费 `required_pairs` 生成 `required_search_groups`，保留 legacy fallback。
`kg_raw_codex/pipeline.py` 的 `_agent_prompt` 将必搜对渲染为显式「术语搜索义务」
中文指令段。

### 2.2 领域对象/否定语境/歧义门控（Step 2）

`data/kg_v2/terminology/context_policies.json` 从 3 条扩展到 11 条，新增：

- 接口类：`PCIe接口`、`HDMI接口`、`CXP接口`、`SMEMA接口`、`PLC控制器`；
- 歧义安全类：`Windows PE`（接地/电气语境拦截）、`SPI设备`（总线/协议语境拦截）、
  `Mark点`（文档/Markdown 语境拦截）；
- 实体别称类：`工控机`、`PCB`、`运动控制卡`、`DL算法`（含英文上下文词）；
- 收紧：`USB接口`、`回流焊设备`、`设备驱动程序` 的 block 词。

同时修复两个确定性匹配问题：

- **多义消歧**：当一个表达同时存在「自指 canonical」和「非平凡等价」
  （如 `运控卡`→`运控卡` vs `运控卡`→`运动控制卡`）时，优先非平凡映射
  （`prefer_non_trivial_mapping`）；
- **2-char Latin token 边界**：`normalize_term` 会去掉空格导致 `DL`/`PE` 等
  短缩写无法按 token 匹配，`_expression_matches` 新增 `original_query`
  按原文空白边界匹配。

### 2.3 证据选择器排除术语治理目录（Step 3）

`terminology_contract.py` 的 `terminology_governance_authority_errors` 与
`_is_governance_path` 覆盖整个治理命名空间（`noun_*`、`review_queue`、
snapshot 等）。本次在线 smoke 中已实际触发：模型把
`data/kg_v2/terminology/noun_terminology_inventory.json` 当作证据引用时被
verifier fail-closed 拒绝，证明隔离生效。

### 2.4 解析器与契约一致性（Step 4）

针对 08-04 报告的 19 题差异，本轮通过门控数据与匹配逻辑修复了：

- 缺失关系：`运控卡 → 运动控制卡`、`DL → DL算法`（entity ontology 已有
  approved alias，本次修复使其在 2-char/多义场景下正确命中）；
- 过宽扩展：`驱动`、`回流焊`、`USB` 等在错误语境下被上下文策略拦截。

### 2.5 外链/媒体/方法变体校验作用域（Step 5）

- `_discover_required_procedure_variants`：闭合 task facet 的来源超过 5 个时
  跳过方案变体强制闭包（宽召回知识题不触发 SOP 重写）；
- `verify_answer_draft` 图片校验按 `read_set` 限定：只校验实际读取文档
  的物化图片，避免无关来源图片造成误报。

## 3. 离线验证方法与结果

脚本：`scripts/verify_terminology_offline.py`（60 题全量，无 LLM）。

```text
must_resolve 命中       : 63/63 (100.0%)
required_search_pairs   : 36/36 (100.0%)
must_not_resolve 正确   : 10/10 (100.0%)
blocked_expansions 总数 : 3
ambiguous_surfaces 总数 : 3
所有必搜对都生成的题    : 60/60
```

- `must_resolve` 覆盖 63 个规范名要求（部分题要求多个），全部命中；
- `required_search_pairs` 覆盖 36 个「原词→规范名」必搜对（如
  `复盘站→复判站`、`运控卡→运动控制卡`、`DL→DL算法`、`码枪→扫码枪`），
  全部生成进搜索契约；
- `must_not_resolve` 覆盖 10 个安全负例（`驱动`、`回流焊`、`USB` 协议、
  `PE` 接地、`SPI` 总线、`Mark` 文档等），全部未被错误解析/锁定；
- 3 个 blocked 扩展即 `驱动→设备驱动程序`、`回流焊→回流焊设备`、
  `USB→USB接口` 的错误语境拦截。

## 4. 在线 A/B 复跑状态

- 2026-08-05 尝试以 DeepSeek V4 Flash（`deepseek-v4-flash`，Chat Completions）
  作为在线运行时跑小批量 A/B；
- 新增 `src/debug_agent_system/kg_raw_codex/deepseek_runner.py`，支持
  `--runtime deepseek`，含 JSON 容错解析、`data/extracted_docx` 视图路径
  规范化、图片 asset_path 引用约束、收敛引导；
- 实测结论：**DeepSeek V4 Flash 不支持严格 `json_schema` 结构化输出**
  （仅 `json_object`），agentic 引用纪律弱，A/B 两臂均因模型自身错误
  （`unknown_image_path`、`covered_facet_without_source`、
  `terminology_governance_material_used_as_evidence` 等）无法稳定通过
  本地 verifier。失败与 `terminology_enabled` 无关，属于运行时噪声；
- 因此正式在线 A/B 复跑应等待 Codex CLI 额度（`gpt-5.6-luna`，预计
  2026-08-10 重置），并使用与 08-04 相同的 `codex_cli` 运行时以保持可比性。
