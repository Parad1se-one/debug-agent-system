## 1. 当前先读什么

按下面顺序阅读即可理解当前管线：

1. [读侧管线组织方式总览](读侧-管线组织方式总览.md)：当前冻结路径、两条扩展路径、v3 shadow，以及一次 Query 的完整生命周期。
2. [Read Runtime v3：设计原理、收益、取舍与相关工作](读侧-Read-Runtime-v3设计原理与取舍.md)：统一目标架构、已落地的 shadow 实现、评测结果和尚未接管的边界。
3. [读侧冻结与 KG_v2+raw Codex 新管线](读侧冻结与KG_v2+raw%20Codex新管线.md)：当前重点优化的独立旁路，包括 Agent 运行方式、Prompt、术语搜索契约、并列方案覆盖和 verifier。
4. [读侧 KG_v2 原生运行时](读侧-KG_v2原生运行时.md)：冻结基线的 Variant、Trace、状态推进、充分性与安全不变量。
5. [KG_v2 读侧主动证据补全与 Codex Tool Harness](KG_v2读侧主动证据补全与Codex%20Tool%20Harness.md)：冻结基线里的 Evidence Gap、Evidence Pack、只读 Tool 和 Codex 编排边界。
6. [读侧 Jira 诊断数据包与 Incident Evidence Runtime](读侧-Jira诊断数据包与Incident-Evidence-Runtime.md)：Query 参考时间窗口、Jira/日志包安全解析、事件相关性、KG 稳定锚点、复现计划与验证报告。

当前存在三条明确隔离的路径：

```text
冻结基线：DebugAgentSystem.start → SAG_v2 → KG_v2 runtime → Evidence Pack → Composer

案件扩展：Query 时间 Scope → Jira/诊断包窗口 → Incident Evidence Pack → KG 假设矩阵 → verifier

独立旁路：Query → KG_v2+raw Codex Agent → 通用只读搜索/阅读 → 本地 verifier

v3 shadow：冻结基线 + KG/SAG + raw + Incident + 请求上下文
           → Evidence Fabric → Planner → Policy → Verifier → shadow diff
```

不要把冻结路径和两条扩展路径的 Prompt、工具、状态机或评测结果混为一套旧实现。
Read Runtime v3 是统一适配层，当前已可以 shadow 运行，但尚未切换正式 `answer/status`。

## 5. 文档维护规则

1. 当前行为只更新“当前总览”和对应路径的实现文档。
2. 大型逐题回答、内嵌图片 HTML 和批次 JSON 默认写入 `data/results/`，不提交到 `docs/`。
3. 生成报告必须写明数据 revision、Prompt/model、生成时间和是否实际复跑。
4. 被新实现替代但仍有复现价值的文档移入 `docs/archive/read-side/<date>/`；纯生成且可重建的大文件直接删除。
5. 历史报告不回写新结论，只修复必要的链接和归档说明。
